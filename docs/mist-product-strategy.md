## 一、为什么转方向

### 1. 外部信号

参考产品 **Netcatty**（继 MobaXterm / SecureCRT / Termius 之后被推荐的新 SSH 客户端）：
- 核心创新点：**把 SSH 终端塞进聊天框，用对话代替命令行输入**
- 用户用自然语言说"帮我查 prod-1 的磁盘"，AI 自动连服务器、执行、返回结果
- 弱化人工输入、强对话驱动 → 跟 Cursor 砍掉开发模式只留对话模式是同一个思路

### 2. 内部判断

- MistTerm 现在还是"人在终端前敲命令"的安全工具形态，天花板低
- Netcatty 已经验证了用户需求真实存在
- 团队里原有方向（A: CLI 工具分发 / B: Prompt 协作等）经过讨论后都觉得"刚需不足"或"偏离过远"
- **不能再走老路**：单纯做安全/凭据/审计这一层，客单价上限低

### 3. 战略意义

MistTerm 从"安全工具"升级为"运维 Copilot"：
- 客单价：从一年几千 → 一年几万到几十万
- 客户群：从中小团队 → 政企/金融（愿意为私有化 AI 付费）
- 故事性：天然适合融资/PR

## 二、新方向定位

**MistTerm AI Agent（对话驱动运维）**：
> 用户在 MistTerm 里说一句话 → Agent 自动选目标机器 → 自动用 MistTerm 的凭据去连 → 自动执行命令 → 把结果用人话总结回来 → 整个过程有审计日志。

**一句话总结**：给 MistTerm 装一个 AI 大脑，从"SSH 工具"变成"运维 Copilot"。

---

## 三、差异化优势（国内没人在做）

1. **私有化部署**：代码、凭据、审计全在内网，敏感行业合规刚需
2. **懂团队权限**：Agent 自动遵守 MistTerm 的团队/用户/角色规则，不会越权
3. **可审计可回放**：每次 AI 执行了什么命令、用了谁的凭据、连了哪台机，全部留痕

## 四、MVP 拆解（4-6 周出 alpha）

1. **对话入口**：在 MistTerm 的会话面板里加一个对话输入框（复用现有 Web UI）
2. **LLM 接入**：后端接 OpenAI/Claude API（先云 API，后面支持私有化）
3. **Agent 工具集**（三个起步）：
   - `list_hosts()` → 拉用户有权访问的主机列表（**复用 MistTerm 权限**）
   - `exec(host, cmd)` → 调后端用 MistTerm 凭据 SSH 执行（**复用 Vault SSH CA**）
   - `read_file(host, path)` → 读文件、SFTP
4. **系统提示词强制走工具**，不准直接编结果
5. **审计日志**：每一步执行都记录（**复用现有审计能力**）

## 五、关键复用点（不白费过去的工作）

- **MistTerm 现有架构**：团队/用户/权限模型 → 直接给 Agent 用
- **Vault SSH CA**：机器身份认证、凭据签发 → 不用重建
- **审计能力**：所有 AI 操作天然可追溯
- **代码片段/snippets 功能**（重要！）：未来 Agent 可以引用团队已沉淀的命令片段，提高准确率
  - 用户说"重启 nginx" → Agent 匹配到 snippets 里"重启 nginx 的标准做法" → 执行
  - 让过去的积累成为 Agent 的"肌肉记忆"

## 六、风险与挑战

| 风险 | 缓解措施 |
|------|---------|
| LLM 编造命令/结果 | 强制走工具、每次执行前确认高危命令 |
| 凭据泄露 | Agent 后端代理执行，AI 永远拿不到明文凭据 |
| 越权操作 | 严格按 MistTerm 团队权限校验，不绕过 |
| 算力/成本 | MVP 阶段用云 API 跑通，验证后再做私有化推理 |
| 客户接受度 | 先做"建议模式"（AI 给命令，人确认后执行），再放开"自动模式" |
