# 中小厂排产/交期 · AI 融合与发散

> 前两份（`01-需求整理.md`、`02-整合稿-给决策看.md`）都在看**过去和现在**：用户的痛点、市场的四层格局、定价区间。
> 这一份看**下一步**：把 AI 叠上去之后，这件事的可能性边界在哪。
> 写这份时我同时翻了我们自己的代码，有个发现放在第一节——比外部调研更值钱。

---

## 一、先说个发现：我们已经有工厂最需要的那副「AI 骨架」

翻 `mist-team-server/internal/ai/` 的时候我愣了一下。我们**已经有一套生产级的 Agent 运行时**，而且恰好是为"高风险操作环境"设计的：

| 我们的能力 | 代码位置 | 对工厂场景意味着什么 |
|---|---|---|
| **Agent 只能提议，不能执行** | `agent.go`：`ProposedAction` 注释明写 *"deliberately inert: the agent can propose, never execute"* | 工厂绝不能让 AI 自己改排产表。这条设计**天生就是工厂要的** |
| **分级授权 + TTL** | `grants.go`：`GrantLevel{safe, readonly, all}`，按 host/riskLevel/isReadOnly/role 判定，带过期 | "允许 AI 改交期，但不允许改已排产"这类规则，现成能表达 |
| **完整审计回溯** | `events.go`（run_start/step/tool_call/tool_result/run_end）+ `trace_repo.go` + `trace_sink.go` | "这单为什么被推迟" → **能回放整个决策链** |
| **敏感信息脱敏** | `redact.go`：`SecretRedactor` 管住 prompt/tool context/log | 工厂的配方、客户名、报价不能进模型 |
| **从日志挖 SOP** | `sop_analyzer.go`：用 LLM 从命令日志里挖操作模式，**自动生成 SOP 文档** | 这就是"沉淀老师傅经验"的工厂版 |
| **运行回放界面** | `web/agent.html`：Agent Trace Replay | 已经有了，不是从零做 |
| **Agentic SRE** | `web/smart-ops.html`：健康巡检、事故现场保全、AI 根因分析、安全自愈 | 这套"出事→保全现场→AI分析→自愈"的流程，**换个对象就是车间** |

**这意味着什么**：别人做工厂 AI 最难的三个问题——**不失控、可审计、能授权**——我们已经解决了。我们缺的不是 AI 能力，是**把对象从"服务器"换成"车间"**。

> 换个角度说：我们擅长的是 **Agentic Ops**（Agent 在真实系统上做可审计的操作）。
> 而工厂排产，本质上就是 **Agentic Ops 的一个新领域**——只不过操作对象从服务器变成了订单、工序、机台。

## 二、AI 给这件事带来的真正变化：从「记录」到「预判」

### 2.1 过去的表格是静态的，AI 时代的关键词是「秒级重排」

这个对比来自真实落地数据：

| | 人工/Excel | AI 排产智能体 |
|---|---|---|
| 插单重排耗时 | **约 2 小时**（大多只是简单顺延） | **约 8 分钟**（全局重新优化） |
| 更激进的案例 | 老师傅 **2 小时**出方案 | 黑湖「拆单 Agent」**5 分钟**出结果 |
| 调度决策周期 | 小时级 | 缩短到分钟级 |

> 注意：这些数字来自厂商，**要打折看**。但"数量级差异"这个结论是可信的——因为人工做的是**局部顺延**，AI 做的是**全局重算**，这是能力性质的区别，不只是快慢。

### 2.2 多智能体不是"更复杂"，而是"各管一段"

工业界的落地形态已经很清楚，**不是一个大模型包打天下**，而是几个小 Agent 分工：

- **订单 Agent** → 解析优先级
- **设备 Agent** → 上报可用产能
- **物料 Agent** → 跟踪齐套
- **协调 Agent** → 协商输出方案

蓝沃在某精密零部件厂的案例（多品种小批量、完全按单生产）部署了**三个专项 Agent**：
- **工艺 Agent** → 解决"工艺依赖工程师经验"
- **排产 Agent** → 解决"排产响应慢"
- **现场 Agent** → 解决"执行不透明"

**这告诉我们**：不要造一个"排产大模型"。要造**三个很小的、各自能单独验证价值的 Agent**。

### 2.3 从「拍脑袋给日期」到「有依据的承诺」

传统：计划员说"大概 25 号"。
AI 版应该给：
- **为什么要这个日期**（哪几道工序、哪个瓶颈）
- **风险在哪**（哪个物料可能晚、哪台机台满了）
- **如果插这一单会怎样**（影响面）

> 💡 **一个发散点子：概率化交期承诺**
> 天气预报早就从"明天晴"进化到"明天降水概率 70%"。但工厂给客户的交期还是**假确定的单一日期**。
> 如果我们给的是「**18 号交货概率 85%，19 号 95%**」——对客户的价值反而更大（他可以按 19 号备货，但知道 18 号大概率行）。
> 而且这个能力**必须建在 AI 上**，人脑算不出来。这是"AI 原生"的典型例子。

### 2.4 从「让人学系统」到「让系统听人话」

百度伐谋 2.0 的一个细节值得注意：**排产师傅用自然语言就能调整决策逻辑**。
在苏州一家注塑厂（1 个月 404 个任务分配到 82 台注塑机）生产率提升 6.31%。

这是对我们「可改公式」优势的**AI 升级版**：
- 今天：用户要学 `=IF(剩余天数<3,"紧急","正常")`
- AI 版：用户直接说「**这个客户的单优先级最高，其他都往后排**」→ 系统翻译成规则

**对中小厂的杀伤力极大**——因为他们的计划员是 4.5K-8K 月薪的普通文员，不是程序员。

## 三、车间是个「语音优先」环境（这条被严重低估）

我专门查了语音报工的落地数据，数字很硬：

| 指标 | 手工输入 | 语音报工 |
|---|---|---|
| 单次报工耗时 | **2-3 分钟** | **20-30 秒** |
| 录入错误率 | 5-8% | **1-2%** |

**为什么这条特别重要**：我们此前的假设是"工人用手机点选报工"，但真实车间里**工人手上是脏的、戴手套的、在动着的**。说话比点屏幕自然得多。

**技术已经成熟且可本地化**：
- 模型：`SenseVoice-Small`、`FireRedASR-AED-L`、`Qwen3-ASR-0.6B`（0.6B 级别，一台 i5 + 8GB 就能跑）
- **本地部署，数据不出厂区，断网也能用** ← 这条对工厂是刚需（配方、客户名不能上云）
- 路线：语音 → 结构化 JSON → 写入系统 → 触发后续流程

**踩坑提醒（业内总结）**：
- **噪音是最大敌人**：普通麦克风在车间基本废掉，必须工业级降噪麦克风（识别率才到 95%+）
- 麦克风离嘴 30-50cm，避开大型机械噪声源
- **要给工人定标准句式**：「工单[编号] [操作] [数量]」，能显著提高识别率
- **权限别省**：最好加声纹识别，分操作工/管理员/工程师三级——否则"谁都能喊一嗓子"

> 我们的独门优势：**Agent 骨架里的 `redact.go` + `grants.go` 正好解决"语音说出来的敏感信息怎么办"和"谁能改"这两个问题**。

## 四、发散：九个方向（按「离现状的距离」排序）

### 🟢 近（现在就能做，复用现有代码）

**方向 1 · 一句话插单预演**
计划员对着系统说：「**把 A123 插到明天**」→ AI 回：「会影响 3 单：B456 延 2 天、C789 延 1 天、D012 延 3 天（其中 D012 客户有违约金条款）。要确认吗？」
- 复用：`propose_command` 模式（**AI 只提议，人确认后才改**）+ 影响面计算
- 这就是我们说的"插单影响面预演"，加个自然语言入口

**方向 2 · 语音报工接入**
工人说「工单 A123 完成 50 件」→ 自动写入 + 更新进度 + 异常触发提醒
- 复用：本地 ASR + 现有 notification
- 差异化：**别人是"扫码报工"，我们做"说话报工"**——扫码要走到二维码前，说话不用

**方向 3 · 交期解释器**
老板问「这单为什么可能晚？」→ AI 基于 trace 回答：「周三那道热处理工序排满了，且铝材到货延迟 2 天」
- 复用：`trace_repo.go` + 事件流
- **这是我们独家的**——没有 trace 能力的厂商答不了这个问题

**方向 4 · 从历史挖「这家厂自己的规则」**（`sop_analyzer.go` 的工厂版）
我们的 `sop_analyzer.go` 已经能从命令日志挖模式生成 SOP。工厂版：从「历史上每次遇到延期是怎么处理的」里挖出**这家厂自己的隐性规则**，然后拿来建议下一次。
- 输出可能是：「你们过去 20 次遇到『铝材延迟』，有 17 次是**先插别的单顶上**，建议这次也一样」
- 这就是**老师傅经验沉淀**的实操形态，不是"存个知识库"

### 🟡 中（需要新增一些东西，但路径清晰）

**方向 5 · 交期「天气预报」**
概率化交期承诺（见 2.3）。基础是**历史实际完工时间的分布**，不需要复杂模型，统计 + 简单回归就能起步。
- 输出：「18 号 85% / 19 号 95%」
- 这是**AI 原生**的，人工做不到，而且是**可以卖给客户看的**（客户也更喜欢这个）

**方向 6 · 例外驱动，而不是排满驱动**
传统 APS 追求"全局最优排程"。但对中小厂，**最优排程第二天就废了**。
AI 版应该反过来：**只在出例外时才介入**——「今天有 3 个例外需要你决策：① 车床坏了 ② 铝材晚到 ③ 客户要加急」。
- 每个例外给 2-3 个选项 + 各自后果
- 这更符合"小厂没法执行复杂计划"的现实
- 复用：`smart-ops.html` 的告警/工单/自愈策略模型

**方向 7 · 「本月还能接几单」**
从交期反推接单能力。老板最关心的问题，但今天没人能答。
- 输入：已有订单负荷 + 产能 + 历史效率
- 输出：还能接 N 单，且**哪些类型能接、哪些不能**
- 和方向 5 共用底座

### 🔵 远（有想象力，但要谨慎）

**方向 8 · Agent 进微信群**
工厂的沟通本来就发生在微信群。能不能让 Agent 在群里听懂「这单先做」并自动落到排产表？
- 诱惑很大（零迁移成本，不改变任何习惯）
- 但风险也大（群里的话有歧义、有玩笑、有变更反悔）
- **可行路径**：Agent 只做"**监听 + 提议**"，在群里回一句「收到，建议把 A123 提到 B456 前面，回复『确认』执行」——**永远不直接改，永远等人确认**
- 这正好又落回我们 `ProposedAction` 的设计

**方向 9 · 对外进度页**
客户能看到自己订单的进度和交期置信度，减少催单电话。
- 复用：`share.go`（只读外链分享）
- 但要注意：**别暴露其他客户的信息、别暴露利润相关信息**

## 五、反直觉的三条：AI 时代「不该做什么」

这一节可能比上一节更有用。

### ❌ 1. 不要做「黑灯工厂」叙事
三一的灯塔工厂：效率 +35%、能耗 -20%。但**关键不是 AI，是"数据底座先行"——那步棋他们下了十几年**。
中小厂没有这个底座，学不了。**用大厂案例去说服小厂，只会让他们觉得自己做不到。**

### ❌ 2. 不要做设备数据采集
这是 AI 落地的**最大陷阱**。三一的例子说明：**AI 的起点不是买大模型，而是先把设备数据采上来**。
但设备采集需要：PLC 改造、协议适配、IoT 网关、现场施工……这是**另一个赛道**，不是我们的能力，也不是我们该花的钱。
> **我们的数据源应该是"人说的话"和"表里的数"，不是传感器。**

### ❌ 3. 不要做视觉质检
看起来是 AI 最成熟的应用（也是很多厂商推的），但：
- 它需要相机、光源、产线改造
- 它是**硬件生意**，不是软件生意
- 它的 ROI 计算完全不同（省的是质检员人力）
**而且**：已经有厂商把"小工厂上AI最省钱的入口**不是质检**"当标题来写——业内已有共识。

> **我们的定位应该坚定在**：不碰硬件、不碰 OT、只做"**信息和决策层**"的 AI。

## 六、收敛：如果只能选一条路

把上面的东西压成一个判断：

> **我们会做的，是一个「车间里的 Agentic Ops」——它不控制机器，它管的是承诺和风险。**

具体说，它做三件事：
1. **看懂**（订单、工序、物料、人的话 → 结构化）
2. **算清**（插单影响面、交期置信度、风险清单）
3. **提议**（给人 2-3 个选项 + 各自后果，人确认后才生效）

而它和我们已有能力的对应关系是：

| 它要做的事 | 我们已有什么 |
|---|---|
| 看懂结构化数据 | sheet + 公式引擎 + xlsx 导入 |
| 看懂人的话 | 需新增：本地 ASR |
| 算清影响面 | 需新增：排产模型（轻量）+ 历史统计 |
| 提议而非执行 | ✅ `ProposedAction`（**已有且是核心设计**） |
| 可授权 | ✅ `grants.go`（GrantLevel + TTL） |
| 可回溯 | ✅ `trace_repo.go` + `agent.html` 回放 |
| 不泄密 | ✅ `redact.go` + 私有化部署 |
| 沉淀经验 | ✅ `sop_analyzer.go` |

**八个里已经有一大半。缺口只有两个半：ASR、轻量排产模型、历史统计。**

## 七、方案演进：三步走

### 第一步 · 交期看板（无 AI，但必须有）
一张排产表 + 剩余天数公式 + 条件高亮 + 分级提醒（T-7/T-3/T-1/逾期）+ 企微推送 + 今日待交一屏。
**为什么必须先做**：因为**没有干净的订单/日期数据，AI 是空转**。这也正是"中小厂卡住的两道关"里的第一关。
**复用**：sheet、formula、notification、webhook、xlsx

### 第二步 · AI 提议层（轻 AI，接在第一步上）
- 插单影响面预演（自然语言入口）
- 交期解释器（基于 trace 回答"为什么可能晚"）
- 例外驱动面板（每天只看几个例外，不是看整张表）
**复用**：`internal/ai/` 全套（ProposedAction / grants / trace / redact）
**这一步是"能不能打动用户"的分水岭**——因为从这里开始，产品会说话。

### 第三步 · 语音 + 预测（重 AI，需要新增）
- 本地 ASR 语音报工（2-3 分钟 → 20-30 秒）
- 概率化交期承诺（历史分布 → 置信度）
- "本月还能接几单"
**新增**：ASR 引擎、历史统计、轻量排产模型
**这一步是护城河**——因为一旦有了历史数据，后来者很难追。

## 八、最后一句

对中小厂，AI 的价值**不是"更聪明"，而是"更敢承诺"**。

一个 30 人的加工厂老板，今天不敢接大单，不是因为不想，是因为**他不知道自己能不能做到**。
AI 如果只能帮他把表填得更快，那没意义。
但如果能让他**知道"这个单我有 90% 把握 18 号交"**——那他就敢接。

**这就是我们从"记录工具"走向"决策副驾"的全部理由。**
